# Банк пінів для Pinterest

Офлайн-інструмент: генерує картинки пінів 1000×1500 і файли імпорту в Pinterest.
У збірку сайту не входить — `astro build` про нього не знає, у `package.json` нічого додавати не треба.

## Файли

| Файл | Що це |
| --- | --- |
| `build-manifest.mjs` | **Джерело правди.** Копірайт українською, вибір фото і кадрування для кожного піна |
| `pins.json` | Згенерований плаский маніфест — з нього працюють рендер і CSV |
| `template.mjs` | HTML-шаблон пінів: чотири розкладки в дизайн-системі сайту |
| `render-pins.mjs` | Рендер картинок у `public/pins/` через Playwright |
| `build-csv.mjs` | Файли імпорту в `scripts/pins/export/` |

## Як користуватися

```bash
npm i -g playwright                      # Chromium уже в PLAYWRIGHT_BROWSERS_PATH

node scripts/pins/build-manifest.mjs     # маніфест із таблиці копірайту
node scripts/pins/render-pins.mjs        # усі піни → public/pins/
node scripts/pins/build-csv.mjs          # CSV → scripts/pins/export/
```

Корисні прапорці:

```bash
node scripts/pins/render-pins.mjs --only=vesilnyi       # перерендерити один пін або групу
node scripts/pins/render-pins.mjs --out=/tmp/preview    # не чіпати банк, подивитися чернетку
node scripts/pins/build-csv.mjs --start=2026-09-01 --per-day=8   # проставити дати публікації
node scripts/pins/build-csv.mjs --flatten               # описи в один рядок, якщо імпорт не любить переноси
node scripts/pins/build-csv.mjs --order=manifest        # без перетасовки, у порядку маніфесту
```

## Розкладки

| Літера | Вигляд | Для якого фото |
| --- | --- | --- |
| **A** | Фото 1000×1000 зверху, червона пунктирна «строчка», кремова панель із заголовком | будь-яке |
| **B** | Фото на весь пін, темний градієнт і білий текст унизу | вертикальне або 3:2 |
| **C** | Фото на весь пін, кремова картка по центру, червона плашка з доменом унизу | 3:2 і вужче |
| **D** | Заголовок зверху, фото-смуга посередині, хук і домен унизу | широке, від 1.8:1 |

A і B повторюють піни першої партії (липень–серпень 2026), C і D додано пізніше,
щоб на той самий URL можна було ставити свіжий креатив без дублювання картинки.

## Кадрування

- `focus` — `background-position` фото (працює по осі, де `cover` дає перекриття);
- `zoom` — масштаб кадру;
- `pan` — зсув **після** масштабування; потрібен там, де `focus` по осі не діє
  (широке фото у високій рамці). Формула: `pan Y = (0.5 − цільова частка по висоті) × zoom × 100%`.

## Іменування

`public/pins/pin_<slug>_<варіант>.jpg` → публічний URL `https://ridnavyshyvka.com.ua/pins/pin_<slug>_<варіант>.jpg`.
Це і є `Media URL` для Pinterest, тож піни мають лежати в `public/` і бути задеплоєні **до** імпорту.

## Файли імпорту

- **`export/pinterest-bulk.csv`** — рівно ті вісім колонок, що очікує масове завантаження Pinterest
  (`Title, Media URL, Pinterest board, Thumbnail, Description, Link, Publish date, Keywords`).
  Колонки для alt-тексту у цьому форматі немає.
- **`export/pins-make.csv`** — усі поля, включно з `alt_text`, для сценарію Make або Pinterest API.

Назви дошок у колонці `Pinterest board` мають збігатися з назвами дошок в акаунті — інакше рядок не імпортується.

## Порядок і час публікації

У маніфесті піни лежать групами по сторінці, тож `build-csv.mjs` перетасовує їх перед експортом:
варіанти одного URL розходяться на кілька днів, а сусідні піни йдуть на різні дошки.
Без цього в перший же день пішло б три піни на одне посилання.

`--start` + `--per-day` проставляють колонку `Publish date`. Слоти дня рівномірно
розкидані між 08:00 і 20:45; час — у часовому поясі акаунта Pinterest, у CSV його не передати.

## Обмеження Pinterest

- `Title` — до 100 символів, `Description` — до 500 (перевіряється в `build-manifest.mjs`);
- один CSV — до 200 пінів;
- планувати публікацію можна максимум на 30 днів уперед.
